# 第 3 章概念 · 记忆与知识库的分层地图

第 3 章的实验很多（3-1 到 3-12），但都在回答一条流水线上的问题：**外部信息怎样变成 Agent 当前上下文里有用的证据**。把它拆成"存、取、查"三层，每个实验就能对号入座。

## 三层地图 → 四个实验

```text
外部世界（会话历史 / 文档库）
   │
   ├─ 存：什么值得长期保留？以什么形状？      → 3-1/3-2 记忆四模式
   │        （会话 → 记忆状态，原文蒸发）
   │
   ├─ 取：文档切块后怎么让"块"可被找到？      → 3-10 上下文感知检索
   │        （前缀 + BM25/稠密/混合三通道）
   │        └→ 3-4 稠密向量怎么高效近邻搜索？（ANNOY/HNSW）
   │
   └─ 查：一次检索不够怎么办？                → 3-8 Agentic RAG
            （模型看着结果决定再搜什么）
```

存与取的分界：**记忆**服务"这个用户是谁"（个性化，跨会话、可更新、有冲突）；**知识库**服务"世界的事实是什么"（共享、量大、只读为主）。两者最终都通过"检索 → 塞进当前上下文"起作用——与 [task1 的信息位置表](../task1/concepts.md) 一脉相承。

## 五个核心概念

| 概念 | 一句话 | 实验锚点 |
| --- | --- | --- |
| 记忆状态替换 | 每会话后只保留"状态"不保留原文；丢进状态之外的事实永久丢失 | [3-1/3-2](memory-modes.md)：layer3 幻觉的根源 |
| 记忆形状 | 原子事实 / 带上下文段落 / 层级 JSON / 全字段卡片——形状决定跨会话连接能力与写手出错面 | [3-1/3-2](memory-modes-code.md)：enhanced_notes 完胜 |
| 孤儿块问题 | 切块后文本失去文档语境，字面与语义都难匹配；前缀（LLM 生成的"身份证"）修复 | [3-10](contextual-retrieval.md)：三通道 MRR 全升 |
| 检索通道互补 | BM25 抓精确词、稠密抓语义、RRF 无权融合——单通道弱时混合有救，单通道强时边际趋零 | [3-10](contextual-retrieval-code.md)：hybrid 追平 dense |
| 迭代检索 | 单查询装不下多跳问题；让模型分解问题、看结果再搜（预算内），召回 0.58→0.92 | [3-8](agentic-rag.md)：三假设全成立 |

## 三方契约：写手、答题者、评审

3-1/3-2 和 3-8 共用一套评审契约（ledger 说明 3-9/3-11 也复用它）：

```text
写手   只见 旧状态 + 新输入          （看不到未来问题——必须猜什么值得记）
答题者 只见 最终状态/证据 + 问题     （看不到任何原文——只能靠存取层）
评审   独享 全部原文 + 答案          （跨厂商，四维分数 + 幻觉一票否决）
```

这个不对称结构把"记忆/检索系统好不好"从"模型聪不聪明"里剥离出来：答题者拿不到的信息，存取层没送到就是没送到；编造了就是幻觉一票否决。**客观指标（证据召回、引用有效性）与语义评审（正确性四维）互补**——前者不经过任何模型，后者管语义质量。

## 与前两章的连接

- **与 2-10 压缩**：记忆状态替换就是"会话级的老化压缩"——enhanced_notes 是它的 context_aware 版（保留什么由"未来有用性"决定），windowed 是它的保守版（满了才压）。差别在第 3 章引入了**评审**，让"压缩丢了什么"变成可打分的问题；
- **与 2-3 KV Cache**：记忆写手每轮 `json.dumps(memory)` 重建 prompt——状态膨胀不仅费 token 也毁前缀缓存。记忆形状越"紧凑可追加"，缓存越友好（advanced_json_cards 的体积劣势在这里还有第二重成本）；
- **与 2-9 状态栏**：TODO 列表是"任务内的短期记忆"，由工具维护、模型只能通过调用改变——与记忆状态"由写手独占写入"同一设计哲学：**状态不靠模型自觉，靠通道约束**。

## 对自己的项目有什么用？

**老师（客服）项目**：

- 用户画像层用 enhanced_notes 形状（带上下文段落）而不是原子标签——客户"上周说过要用工资卡还款、这周换了卡"这种演变，原子标签只能存最后一个值；
- 高风险记忆（投诉历史、承诺记录）值得 advanced_json_cards 的"冲突保序"——新旧声明并存，回放时能看出谁先谁后；
- 知识库侧：政策文档切块后按 3-10 加前缀（"本块来自《XX 退票政策》第 3 条"），客服检索的 R@1 直接受益；政策查询多为单跳，Agentic 检索的迭代收益主要在多保单联动的复杂工单。

**实时对话项目**：

- 对话历史分龄：近 N 轮原文（实时细节），更早按 enhanced_notes 摘要成用户状态（3-1 的模式直接可用）；
- 多轮澄清问题（"你刚才说的 X 是哪个"）本质是 3-8 的迭代检索——单轮拿不全上下文时，让模型主动发起第二次"查历史"而不是猜；
- 评审契约可借来做回归测试：新版本记忆系统的答案让独立模型按四维 + 幻觉否决打分，防止"改了存储格式、悄悄丢了事实"。

具体字段要回到两个项目的代码再确认，这里只建立对应关系。
