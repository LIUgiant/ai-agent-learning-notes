## 这个实验回答什么问题

文档切块后，每一块都成了"孤儿"——《宪法》序言里的一句话，单看既不知道来自哪份文档、属于哪一章，BM25 和向量检索都容易把它和别的"法律成果"混在一起。**Anthropic 的 Contextual Retrieval** 方案：给每个块用 LLM 生成一段"上下文前缀"，前缀 + 原文一起进索引。问题：前缀对 BM25、稠密向量、混合检索各有多少提升？索引成本增加多少？

## 设计

六方法对照：plain（原文索引）vs contextual（前缀+原文索引）× BM25 / 稠密（本地 Qwen3-Embedding-0.6B） / RRF 混合。**同一批 chunk、同一批查询**，唯一变量是索引文本有没有前缀。指标 recall@1/3/5 与 MRR，15 条标注查询（金标 chunk 已知）。

语料与规模：宪法 + 检察官法，22 chunk，15 查询——**与书方全量同规模，不抽样**。一个前置事实：课程仓库不带 document_store.json，学习版从书方已通过战役的证据**无损重建**（chunk 内容逐字节相同、与金标 ID 对齐）；前缀全部由 DeepSeek 现场生成（课程门槛"手写前缀不算数"原样满足）。

**与课程原版的差异**：前缀模型 doubao → DeepSeek（`deepseek-flash`）；pricing 置零（未配置 DeepSeek 价格，成本以 token 用量原样记录）；其余（语料、分块、查询、BM25/稠密/混合实现）课程原样。

## 看结果前先想清楚

1. 前缀对 **BM25** 和**稠密向量**哪个帮助更大？（提示：前缀塞进了"宪法""序言"这些原本不在块里的字面词）
2. 索引阶段 22 次 LLM 调用（每块一次），检索阶段零 LLM——这笔成本什么时候回本？
3. RRF 混合把两个排序融合，前缀的收益会被"平均"掉还是叠加？

## 运行结果

课程验收门槛全过（live 前缀、每请求含完整源文档、真稠密模型、召回/MRR 完整），泄漏扫描干净：

| 方法 | MRR | R@1 | R@3 | R@5 |
| --- | ---: | ---: | ---: | ---: |
| plain_bm25 | 0.833 | 0.73 | 0.87 | 1.00 |
| contextual_bm25 | 0.872 | 0.80 | 0.93 | 1.00 |
| plain_dense | 0.933 | 0.87 | 1.00 | 1.00 |
| contextual_dense | **0.967** | **0.93** | 1.00 | 1.00 |
| plain_hybrid | 0.889 | 0.80 | 1.00 | 1.00 |
| contextual_hybrid | **0.967** | **0.93** | 1.00 | 1.00 |

索引成本（一次性）：22 次前缀调用共 181K tokens（输入 180K——每块请求携带整份源文档）、4 并发 5.5 秒；CPU 编码 59 段 408 秒。查询阶段零增量。

## 分析

- **前缀三通道全部提升**：MRR 上 BM25 +0.039、稠密 +0.034、混合 +0.078；R@1 从 0.73/0.87 → 0.80/0.93（金标排第一的查询 11/15 → 14/15）。BM25 的受益机制最直观——前缀塞进了块里没有的字面词（"宪法""序言""1982"），词频匹配多了一条命中路径；稠密通道同步提升说明前缀也修复了**语义**定位（孤立条文获得了文档语境）；
- **混合的边际条件**：contextual 侧 hybrid 追平 dense（0.967）——稠密通道足够强时，混合加成趋零；但 plain 侧 hybrid（0.889）明显落后 dense（0.933）。**混合救的是"某一通道弱"的场景**（比如同义改写查询下稠密强、精确编号查询下 BM25 强），不是无条件加成；
- **成本结构**：前缀的钱几乎全在输入侧（180K/181K），因为每个请求都带整份源文档——这是"看全文才不会编出处"的代价。查询零增量意味着**回本速度 ∝ 查询量**；对低频查询的语料，这个一次性投入要想清楚；
- **与书方对照**：书方（doubao 前缀 + 同款编码器）MRR：plain_bm25 0.751→0.856、plain_dense 0.922→0.967、plain_hybrid 0.844→0.913——方向与数值区间和本次一致。换前缀模型结论不变，**前缀的收益更像机制性收益而非模型运气**。

**边界**：小语料（22 块）R@5 已触顶（全 1.00）、失去区分度；单金标口径；同义改写查询（BM25 死穴）未测——这些都要更大语料才有分辨力。
