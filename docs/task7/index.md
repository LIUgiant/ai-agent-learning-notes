## 把两章连成一个问题

网页里的内容可能是真的，也可能过时或恶意；写作者的总结可能流畅，也可能遗漏条件。**信息经过一次模型处理，不能因此获得更高的指令权限。**

我们的方案把四种东西分开：

1. **证据**：别人说了什么，有什么原始依据。
2. **提案**：我们建议系统以后怎么做。
3. **验证**：新做法是否正确、有用且没有破坏原有能力。
4. **批准**：谁有权让这个具体版本服务真实用户。

多 Agent 分工也沿用这个边界：搜集者交证据，写作者交候选成果，审核者交独立检查结果；受保护的发布程序最后检查批准与版本是否匹配。

## 与已有项目的联系

- **老师／客服项目**：外部网页或客户聊天不能自动升级为退款、转人工等长期业务政策。可以提出 Skill 修改，但企业规则和权限仍由受保护程序约束。
- **3D AI 老师**：课堂反馈可以形成教学策略候选；学会新的讲解方式，不应使 Agent 获得修改音频权限、数据保留规则或发布审核的能力。
- **学习笔记**：搜集资料与写文章可以分工，独立审核必须检查来源、引用、事实与未完成项，不能把“页面写好了”当成“结论已经证实”。

以上是设计映射，不表示这两个业务项目已经实现本页全部机制。
